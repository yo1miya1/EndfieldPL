## 像素编码与比较方式

源final-with-ui.png为2560×1440，Unity083为1506×846。源RGB用Lanczos一次缩小到Unity原生尺寸，Unity图不重采样。两个宽高比略有差别，不能把边缘上少量重采样误差解释为材质误差。未做位移配准、形变、颜色拟合或曝光调整。表中单位是8位display RGB码值，不是场景线性光强。

源PS2148在doc/capture/post/2148_ps.txt的指令87–99明确执行分段Linear→sRGB，然后加入约0.001373幅度的显示抖动。该输出20681为R8G8B8A8_UNORM，后续UI最后3389也写R8G8B8A8_UNORM资源129（UINative/graphics/eid-3389.json与texture-metadata.json）。所以最终PNG的RGB已经是display编码；它与静态BC7_SRGB贴图导出PNG的“已线性解码”含义不同，不能对最终RGB再次做Linear→sRGB。

源alpha并非最终图整体透明度：其均值37.54/255、中位数15/255，89.44%像素alpha<128，仅0.715%为255。PS2148指令13读取t0 RGBA，指令100把t0保留的alpha附带输出；后续UI继续混合alpha。完整屏幕显示采用RGB，不能按这个附带alpha与黑/白/棋盘底合成后评估。这里convert('RGB')直接去掉alpha，保留RGB字节；没有做预乘或反预乘。Unity截图alpha为255。

## Ink FX 的差异边界

墨纹的主要结点、长笔画方向与覆盖范围已恢复，不是缺少整套特效。上述两个ROI内，源暗像素比例为5.18%/15.60%，Unity为4.41%/13.73%；Unity黑色覆盖稍少。阈值同时受背景亮度、混合、抗锯齿和重采样影响，不能把IoU直接解释为模型错位。

当前九层Source/semantic-effect-bindings.json全部使用固定_InkPhase=206.8019256591797与_InkAnimationSpeed=0；InkEffect.shader中phase=_InkPhase+_Time.y×_InkAnimationSpeed。因此现有证据不支持“Unity采样时刻不同”作为主要理由。源姿态、o5颜色及四组UV也来自本帧PostVS。屏幕随机覆盖使用当前SV_Position的确定性函数；它没有新的时间种子。

仍应优先区分真实噪声纹理采样、mip/导数、黑色Border线性采样、alpha/depth-only层次和当前opaque深度副本造成的覆盖差异。1554/1672/1693/1730确实采当前深度，且原场景与重构场景深度可能不同。源后处理历史/抗锯齿的影响没有在这张最终图中单独隔离；仅凭单帧终图不能把剩余差异全部归给时序，也不能反过来宣称所有源PS分支已逐像素闭合。下一张086+使用同一脚本更新，不以本轮结果作为最终验收。
