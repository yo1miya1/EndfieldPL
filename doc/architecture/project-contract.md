# EndfieldRebuild 工程约定

本轮起始日期：2026-10-27。本文记录用户已明确的范围及本轮实施约定，不把旧工程文档中的操作指令视为新任务授权。

## 目录和所有权

| 目录 | 内容 | 规则 |
| --- | --- | --- |
| `pro/` | 可直接用 Unity Hub 打开的 Unity 主工程 | `Assets`、`Packages`、`ProjectSettings` 直接位于此处 |
| `doc/` | 设计、证据摘要、进度、决策和使用说明 | 区分直接观察、推断、验证结果和待办 |
| `src/` | 原始输入 `SI-1.rdc` | 只读；回放使用经过 SHA-256 验证的独立工作副本 |
| `tool/` | 必须修改的外部工具副本 | 修改前复制，记录上游路径、版本及改动理由 |
| `tmp/` | 回放中间产物、日志、测试图和构建输出 | 按 capture、Unity、build 等用途分类；不作为运行依赖 |

旧工程 `F:/Project/_Game/EndfieldRendering` 仅作为只读参考。新运行工程不能引用旧工程绝对路径，不能依赖旧角色、旧场景或旧生成目录。

## 职责和约束

管线 Asset 保存配置；RenderPipeline 管理相机入口和剔除；Renderer 管理阶段；各 Pass 管理本阶段输入输出。顺序为 Shadow → Outline → GBuffer → Lighting → Transparent → PostProcess → UI。GBuffer 的布局可继承经核实的设计，附件所有权与传递机制重新实现。

角色材质按 Hair、Cloth、Face、Eye 等语义功能选择变体，纹理、常量、状态由材质承载。公共公式有清楚的输入输出。Unity 提供当前相机、对象变换、可见光源和阴影剔除；无法从截帧稳定取得的通用行为参考当前 Unity 实现。

源截帧的 GBuffer、深度、阴影、历史和最终画面只用于对照，不成为实时渲染的替代输入。UI 的翻转在 UI 接口内处理，不用最终全屏翻转掩盖几何或坐标错误。捕获姿态网格不等于恢复骨骼动画。

## 验收证据

依次核实：输入身份和实际资源绑定；几何/UV/法线和角色居中；Unity C# 与实际 Shader 变体编译；场景可打开和独立构建；固定视角下的深度/GBuffer/光照/后处理/UI；改变光照与相机后仍可正确响应。

“提取成功”“编译通过”“有图像”“与截帧吻合”分别记录。不得用后者的措辞替代前者，也不得把未验证的通用 Toon/PBR 响应称为源公式还原。

用户进一步指定：主会话已设置 Astra；自主推进直到任务完成或额度耗尽。使用 Unity 6，不使用 Computer Use。最终验收必须包含 Unity 编辑器截帧对比和编辑器截图对比；通过 Editor API、命令行及 RenderDoc API 采集，避免依赖 GUI 自动化。

用户再次收窄实施方式：直接修改工程，复用旧项目的算法、工具和已完成验证，不重复通用调研和预防性测试。只补新角色必需的资产/绑定差异；在实际运行报错或图像偏差出现后定位问题。保留用户要求的最终编辑器截图和截帧对比。
